# AGENTS.md — working protocol

Applies to coding agents and humans alike. Read this fully before your first commit.

---

## 1. Before you write any code

1. Read `SOURCE_OF_TRUTH.md` §1–§5. The invariants in §2 are laws, not suggestions.
2. Find your task ID in `PROJECT_STATUS.md` §4. If it isn't there, it isn't approved work — add it as a new row with status `TODO` and flag it in §6 Open Questions rather than silently building it.
3. Check the **Depends** column. If a dependency isn't `DONE`, build against its **stub**, not against nothing and not by reaching into another block's internals.
4. Claim the task: set Owner and status `WIP` in the same commit as your first code change.

## 2. Scope discipline

- **You own one block.** Edit only the directories your block owns (`SOURCE_OF_TRUTH.md §5`).
- Need a change in another block's directory? Do not make it. Open a row in `PROJECT_STATUS.md` §6 naming the block and the change you need, and work around it with a stub in the meantime.
- Need to change a **contract** (`§4`), an **invariant** (`§2`), the **vocabulary** (`§3`), or the **head registry** (`§6`)? Stop. Write an ADR in `docs/adr/`, add the row to `SOURCE_OF_TRUTH.md §12`, and get a human to accept it. Contract drift is the one failure mode that silently destroys a parallel build.

## 3. Status update protocol — do this every time

On **every** status change, in the same commit as the work:

1. Update the task row in §4: `Status`, `Owner`, `Artifact` (a path, PR number, or report link — never blank on `DONE`), and `Notes`.
2. Update the block rollup in §3 (`Done / Total`).
3. Update the milestone rollup in §2 if the change completes a milestone item.
4. **Append one line to the §5 Changelog.** Never edit or delete an existing changelog line.

```
2026-03-04T11:20Z | agent-b4 | B4-T06 | WIP -> REVIEW | PR #142, mlruns/exp7 | Stage 1 EER 2.4% on ASVspoof5 dev
```

Rules that matter:
- **`DONE` requires the Definition of Done** from `IMPLEMENTATION_PLAN.md` to be genuinely satisfied, plus a recorded artifact. "It runs on my machine" is `REVIEW`, not `DONE`.
- **`BLOCKED` requires naming the blocker** — a task ID or a person — in Notes, plus a row in §7.
- **Never renumber or delete a task row.** Use `DROPPED` with a reason.
- If you discover new required work, add new task IDs at the end of that block's table (`B4-T11`, `B4-T12`, …). Never reuse a retired ID.

## 4. Definition of Done, universally

A task is `DONE` when all of these hold:
- Code merged to main, CI green.
- Tests exist: unit tests for logic, at least one integration test for anything crossing a service boundary.
- The block's Definition of Done in `IMPLEMENTATION_PLAN.md` is satisfied.
- Contracts respected — outputs validate against `schemas/`.
- Artifact recorded in `PROJECT_STATUS.md`.
- If it's an ML task: the config is committed, the run is reproducible from that config, and the numbers came from `make eval`, not from a notebook.

## 5. Rules specific to ML work

- **No number without a protocol.** Any EER, accuracy, or latency figure that appears in a doc, a slide, or a commit message must trace to a row in `docs/benchmarks/REPORT.md` generated by B15. Numbers remembered from papers are context, never claims about our system.
- **Report degradation honestly.** Cross-dataset numbers will be much worse than in-domain numbers. That is expected and publishing it is a strength. Quietly reporting only the in-domain number is the fastest way to lose credibility with a technical reviewer.
- **Never train on your evaluation set.** In-the-Wild is the honesty check; it is eval-only, permanently.
- **Check the license gate before every training run.** `allow_noncommercial: false` for anything on the commercial lineage.
- **Symmetric augmentation, always** (invariant I3). If you add a new channel transform, it applies to bona fide and spoof identically, and `test_symmetry.py` must still pass.

## 6. Rules specific to the audio path

- Never block. If your component can exceed its budget, it must time out and return `ABSTAIN` (invariant I10).
- Never persist raw PCM on the default path (invariant I5). If you need audio for debugging, gate it behind an explicit dev-only flag that is off in every committed config.
- Never assume 16 kHz input at the edge. Telephony gives you 8 kHz µ-law far more often than anything else.

## 7. Commit and PR conventions

```
<block>: <imperative summary>          e.g.  B2: add hold-music detector to quality gate

Task: B2-T07
Status: WIP -> REVIEW
Artifact: services/conditioner/music_detect.py, tests/unit/test_music_detect.py
```

PRs stay under ~400 changed lines where possible. A PR that touches more than one block's directories needs an explanation in the description.

## 8. When you are stuck

In order:
1. Re-read the relevant `SOURCE_OF_TRUTH.md` section — most ambiguity is answered there.
2. Build against a stub and keep moving.
3. If it's a genuine decision (not an implementation detail), add it to `PROJECT_STATUS.md` §6 Open Questions with your recommended answer and the tradeoff, and continue on something else.
4. Do not invent a contract, a threshold, or a dataset license interpretation to unblock yourself. Those three are exactly the things that must not be guessed.

## 9. Things no agent may do without explicit human approval

- Clone the voice of any real person who has not signed the consent register (invariant I9).
- Send audio, transcripts, or embeddings to any external API or hosted model (invariant I6).
- Ship or demo a model trained on non-commercially-licensed data as a commercial capability (invariant I7).
- Change a default threshold, or remove the `ABSTAIN` state anywhere in the pipeline.
- Present the system as authoritative rather than advisory in any user-facing copy (invariant I1).
